# ETF Dashboard - Comprehensive Functionality Documentation

This document provides detailed technical specifications and functionality overview of the ETF Dashboard application, designed for AI tools, developers, and system understanding.

---

## 🏗️ System Architecture

### Technology Stack
- **Backend**: Node.js + Express.js
- **Frontend**: React 18 with modern hooks
- **Data Sources**: AMFI (NAVAll.txt), mfapi.in, NSE (live scraping)
- **Web Scraping**: Puppeteer for live NSE data
- **Storage**: File-based JSON storage (daily files)
- **Caching**: In-memory caching with TTL
- **Deployment**: localhost:3000 (frontend), localhost:5000 (backend)

## 🔧 Core Functionality Details

### 1. Automated ETF Data Fetching & Categorization

#### Data Sources Integration
- **Primary Source**: AMFI NAVAll.txt (official mutual fund NAV data)
- **Secondary Source**: mfapi.in API (backup/validation)
- **Live Source**: NSE website (real-time pricing)

#### Categorization Logic
The system uses intelligent keyword matching and rule-based categorization:

```javascript
// Example categorization rules
const CATEGORY_RULES = {
  'Large Cap': ['NIFTY 50', 'SENSEX', 'LARGE CAP'],
  'Mid Cap': ['NIFTY MIDCAP', 'MID CAP'],
  'Small Cap': ['NIFTY SMALLCAP', 'SMALL CAP'],
  'Sectoral': ['BANK', 'IT', 'PHARMA', 'AUTO', 'METAL'],
  'International': ['NASDAQ', 'S&P 500', 'INTERNATIONAL'],
  'Commodity': ['GOLD', 'SILVER', 'COMMODITY'],
  'Debt': ['GILT', 'BOND', 'DEBT']
};
```

#### Data Processing Pipeline
1. **Fetch**: Download NAVAll.txt from AMFI
2. **Parse**: Extract ETF entries using regex patterns
3. **Filter**: Remove "Regular" and "IDCW" variants
4. **Categorize**: Apply rule-based categorization
5. **Validate**: Cross-reference with mfapi.in
6. **Store**: Save as daily JSON file with timestamp

#### File Storage Pattern
```
nav_data/
├── nav_data_2025-06-24.json
├── nav_data_2025-06-23.json
└── nav_data_2025-06-22.json
```

### 2. Robust API Backend Specification

#### API Endpoints

**GET /api/etfs**
- **Purpose**: Retrieve all categorized ETFs
- **Response**: Array of ETF objects with full details
- **Caching**: 1-hour TTL
- **Error Handling**: Returns 500 with error message if data unavailable

**GET /api/categories**
- **Purpose**: Retrieve all available ETF categories
- **Response**: Array of category names
- **Logic**: Dynamically generated from current ETF data

**GET /api/etfs/category/:categoryName**
- **Purpose**: Retrieve ETFs filtered by specific category
- **Parameters**: categoryName (URL parameter)
- **Response**: Array of ETF objects in specified category
- **Validation**: Returns 404 if category doesn't exist

**GET /api/nav/:schemeCode**
- **Purpose**: Retrieve specific ETF NAV data
- **Parameters**: schemeCode (6-digit scheme identifier)
- **Response**: Single ETF object with detailed NAV information
- **Validation**: Returns 404 if scheme not found

**POST /api/refresh-nav**
- **Purpose**: Manually trigger NAV data refresh
- **Response**: Success/failure status with timestamp
- **Process**: Initiates full data fetch and categorization pipeline

**GET /api/live-data/:symbol**
- **Purpose**: Retrieve live ETF data from NSE
- **Parameters**: symbol (NSE trading symbol)
- **Response**: Live price, volume, and market statistics
- **Technology**: Puppeteer-based web scraping

#### Caching Strategy
- **In-Memory Cache**: Redis-like structure using JavaScript Map
- **TTL**: 1 hour for NAV data, 5 minutes for live data
- **Auto-Refresh**: Automatic cache invalidation and refresh
- **Fallback**: File-based storage if cache fails
